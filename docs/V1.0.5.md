# Version 1.0.5 – Alexa-Befehle bei sichtbarem Dashboard

20. Oktober 2026

Beim LaunchRequest werden RenderDocument und shouldEndSession: true gemeinsam gesendet. Kein Finish, keine Sprachausgabe und kein reprompt. Touch- und automatische APL-Aktualisierungen verwenden ebenfalls shouldEndSession: true, damit keine neue offene Sprachsitzung entsteht. Stop/Cancel enden still. Der Fallback entspricht der erfolgreich erprobten stillen Testvariante. Direkte Solar-Fragen bleiben erhalten.

Die Bildschirm-Aktualisierung ist auf displayState foreground beschränkt. Andere Alexa-Ansichten werden nicht automatisch wieder von der Solaranlage verdrängt. Amazon entscheidet über Sprachrouting, verbleibende Anzeigedauer und das Ersetzen des Dashboards. Das Beenden einer Sitzung reicht eine bereits abgefangene Frage nicht nachträglich weiter.

## Prüfung und Live-Test

23 Python-Prüfungen bestanden, einschließlich Live-Payload-Verarbeitung, fünf Sprachabfragen, fehlender/veralteter Werte, Refresh, Ablauf und stiller Beendigung. Das zusammengebaute Modul wurde auf Python-3.8-Syntax geprüft. Die entsprechende separate Testversion bestand neun Tests und wurde vom Betreiber am Echo Show erfolgreich erprobt.

Live-Test: „Alexa, öffne meine Solaranlage“, dann sofort Wetter bzw. Lichtsteuerung ansprechen, ohne vorherige Uhrzeitfrage. Auch nach einer Minute Aktualisierung und die Solar-Sprachabfragen prüfen. Für das serverseitige Alexa-Codeupdate ist keine HA-Neukonfiguration nötig. Das HACS-Paket trägt die Versionsnummer 1.0.5; sein Funktionscode ist unverändert.

## Rücksprung auf 1.0.4

Das bestehende [Release v1.0.4](https://github.com/kulmi84/solaranlage-echo-show/releases/tag/v1.0.4) und sein Tag werden nicht gelöscht oder verschoben. Für eine lokale Installation den Quellstand dieses Tags verwenden und `python build_skill.py` ausführen. Das erzeugte Modul `dist/lambda_function.py` im eigenen Alexa-hosted Skill speichern, deployen und bei einem veröffentlichten Skill „Promote to live“ ausführen. Vorhandene relay_config.json beibehalten. Für den gemeinsam betriebenen Skill wird der Rücksprung zentral vom Betreiber vorgenommen; ein HACS-Downgrade allein ändert den Alexa-Code nicht.

Der zuletzt laufende Betreiberstand vor 1.0.5 ist zusätzlich separat mit privater Konfiguration und Prüfsummen lokal gesichert. Private Backups gehören nicht in dieses öffentliche Repository.
